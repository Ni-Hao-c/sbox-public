## 已修正的三条路径

### 压缩纹理的最小 mip

当前 Vulkan 运行环境中，直接上传的 BC1 纹理在 2×2、1×1 层采样为黑色。人工构造的 8×8 纯色 mip 链和原版 BC7 草丛纹理均可重现；因此这不只是 CPU 像素读回转换失败。

`RpakTextureDecoder.PrepareUpload` 在创建运行时纹理前保留尺寸至少为 4×4 的 mip，远距离采样由 GPU 钳制到最后一个有效层。矩形纹理按较短边判断；立方体/数组正确保留每个面的偏移；普通 RGBA 纹理不受影响。原始 RPAK 解码结果和磁盘缓存仍保留完整链，源数据的 16 字节对齐规则没有改变。

控制检查：旧链的采样为黄、蓝、黑、黑；修正后为黄、蓝、蓝、蓝，四项通过。这个修正处理了可重现的远景采样错误。**用户截图中的粉色/绿色亮条，在修改前的本次地图固定视角检查中也没有稳定重现，不能仅凭上述控制检查宣称那些亮条全部消失。**

### Lyr 双层表面的独立 UV

殖民地的 `uberLyrDtnUV20000100000Samp2222222222_wld` 原始程序用 UV0 采样两层颜色、法线、Gloss、Specular 和混合遮罩；8 倍 UV1 变换只用于细节法线。旧实现先统一应用 UV1，再采样所有表面贴图，造成颜色和混合遮罩重复。

材质描述现在解析 UV 选择串，并按已绑定材质纹理的寄存器顺序映射，不能直接用稀疏的 t15、t22 等编号作为选择串索引。共享 shader 分别为每层表面及遮罩选择 UV0/UV1/UV2/UV3；实验光照材质复制时也保留这些参数。纹理布局不完整时保留原路径，避免猜错未知槽位。

GPU 检查使用相同的 8 倍变换和双色遮罩：UV0 只产生一次红蓝交界，UV1 产生 13 次交界，两项通过。

### Lyrtrans 覆盖层的透明度

明显矩形道路来自 `world/dirt/dirt_forest_tracks_01_bm_transparent` 等覆盖层。其 shader 是 `uberLyrtransTransSamp22222_wld`，实际包含 `layerBlendTexture`；旧实现因它不是不透明双层表面而丢弃该贴图。

原版程序和材质常量确认：

```text
weight   = saturate((ramp + 1) * vertexAlpha + ramp * (mask - 1))
coverage = 1 - weight
opacity  = coverage * albedoAlpha * materialOpacity
```

代表道路的 ramp 为 1.61。顶点 alpha 已经参与 weight，不能在最终 opacity 上再次相乘；alpha=1 的边缘可以完全露出下方地形。地图数据确实保留了 0、255 和大量中间顶点权重。

现在保留并绑定该遮罩，给透明网格贴花增加独立的 Lyrtrans 分支。普通贴花仍使用自己的顶点透明度。全显示、全隐藏、半透明以及普通贴花的显示/隐藏，共五组 GPU 检查通过。

## 对“能否像原版一样混合”的回答

可以利用地图已有的双层材质、遮罩和顶点权重还原地形材质之间的过渡，本次已经补齐上述缺失路径。不会增加一轮全屏绘制，也不需要把所有草丛改成普通半透明。

这不等于任意独立模型都能自动与地面融合。草根、岩石模型与地形的交界，如果原素材没有相应遮罩，需要专门的深度淡入或高度混合方案。还应单独校准植被粗糙度、法线、间接光及抗锯齿后的 alpha 覆盖率；原版的光照、雾和曝光也会改变边缘观感。
