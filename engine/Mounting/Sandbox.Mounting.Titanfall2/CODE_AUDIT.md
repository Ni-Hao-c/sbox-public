## 已确认并修复

### 1. 缓存场景丢失代码生成的地形模型

**复现：** 同一进程中打开战争游戏，关闭编辑器场景，等待资源缓存过期，再次打开并运行。静态道具存在，地形与透明块引用的 Model 则变为 `IsError=true`，场景中出现大面积缺地面。

**原因：** `SceneLoader` 缓存的是序列化 SceneFile。地形 Model 由 Model.Builder 生成，只登记弱资源索引，没有磁盘文件或独立重建 loader。关闭最后一个场景后，原模型可以被 GC 回收，但 SceneFile 中仍保留其引用。

**修复：** [Resource/Map.cs](Resource/Map.cs) 在 MapLoader 中保留 WorldBuildResult、生成材质包装及原始碰撞模型，使资源与缓存场景同寿命。光照纹理由缓存构建结果保留，不再交给单个场景克隆析构时释放。挂载卸载后资源 loader 集合被清除，相关引用可随之回收。

**验证：** 首次加载及两次“停止 Play → 关闭地图 → 等待 12 秒并强制 GC → 重新打开 → Play”均通过 `VerifyGeneratedWorldResources.csx` 六项检查：223 个聚合模型、37 个透明块模型及 SKY A/B、RTL A/B 纹理全部有效。飞机可见性五项检查也在重载后通过。

**边界：** 生成资源现在按缓存场景寿命保留，会占用实际内存和显存。这修复了错误资源重载，不等于已经实现跨地图的 GPU LRU 预算。今后的预算淘汰必须同时处理缓存场景及生成资源的重建，不能只释放模型而保留失效引用。

### 2. 双纹理调制被误绑定到顶点色标记

**原因：** 前一轮仅给带 `$vertcoloristint` 的材质启用双纹理乘法。战争游戏浅蓝全息网格没有该标记，仍把图像与噪声相加，亮部偏白。不透明与普通透明程序也仍保留旧的相加实现。

**修复：** [Resource/LegacyMaterial.cs](Resource/LegacyMaterial.cs) 对具有两张有效 2D 纹理的普通 UnlitTwoTexture 统一使用调制；显式 `$addlayers=1` 和第二层 cubemap 保留独立行为。三条 2D shader 通过 `titanfall2_vmt_layers.hlsl` 共享合成函数，避免再次只修一条路径。透明度只调制一次，修正加法路径中 layer alpha 被重复相乘的问题。

**验证：** `VerifyLegacyGrid.csx` 31 项通过，包含三种渲染路径的 24 项 GPU 颜色/覆盖检查，以及七项真实材质检查。测试包含非黑的正例、互斥颜色乘为黑、纹理 alpha、顶点 alpha、层 alpha 和颜色调制；并保留相加回退检查。Live Fire 的实际 cubemap 材质另有路径及维度检查。

**边界：** 真实蓝屏仍受 HDR 显示、曝光、Bloom 和特殊程序影响，不能由该测试推断已达到原版外观。

### 3. 双纹理材质没有执行完整代理链

**原因：** 专用创建分支返回材质后，没有调用代理登记。静态读取 TextureTransform 只能得到初始值，无法执行 `TextureScroll → 中间向量 → TextureTransform`、LinearRamp 旋转、Sine 缩放及透明度变化。旧表达式也没有保存完整的三个变换输入。

**修复：** 在 [Formats/Titanfall2VmtReader.cs](Formats/Titanfall2VmtReader.cs) 中保留向量初值、变换输入和代理源顺序；在 [Resource/MaterialAnimator.cs](Resource/MaterialAnimator.cs) 中执行向量分量噪声、间接滚动、旋转和缩放，并写入专用材质参数。CPU 已执行的滚动/抖动不再由 HLSL 重复执行。普通 Basic 材质原有 shader 滚动保持其路径。

代理组件在编辑器与 Play 中均更新；纯常量材质不登记逐帧程序，代理类型名在登记时规范化，避免每帧重复规范化。

**验证：** `VerifyVmtProxies.csx` 15 项通过，包含确定时刻的变换/透明度、向量分量、禁止重复滚动、显式 addlayers、cubemap 及两项实际 GPU 透明度输出。`VerifyLiveVmtProxies.csx` 三项验证真实场景持续更新旋转、缩放与透明度，且在地图重载后再次通过。

**边界：** 当前覆盖本次实际材质使用的标量缩放、默认中心变换及代理组合；任意二维缩放、变换中心、游戏实体驱动代理和全部定制扩展仍需逐个核对。不能称为完整 Source 材质代理解释器。

### 4. 最后一个场景停止后，缓存材质永久失去代理更新

**原因：** 旧 Deactivate 在计数降为零时清空全部登记；材质仍被资源缓存保留，下次进入地图不一定重新调用材质 loader，因而没有重新登记。

**修复：** 停止最后一个场景时只清理已经失去目标的弱引用，保留活着的缓存材质。组件登记/退出与 OnEnabled/OnDisabled 配对，避免编辑器和 Play 生命周期错配。

**验证：** 确定性测试在最后一个 animator 退出后改变时刻，确认原材质仍能得到新变换与透明度；实际地图的两次重载也继续更新代理。
