# Titanfall 2 STARPAK 索引审阅与修复

日期：2026-10-30。本轮继续检查 RPAK / STARPAK、预取退出和派生缓存。已确认的生产修复集中在 `Pak/StarPakIndex.cs`。

## P2：流式索引可发布越过数据区或相互覆盖的条目

原实现只验证文件末尾的条目数量，然后保留 `offset >= 0 && size > 0` 的记录。它没有验证数据范围是否越过索引起点，也不拒绝重复偏移；重复项由后面的记录静默覆盖。负偏移或非正大小则被静默跳过，使含有损坏记录的索引仍能发布。

`RpakTextureDecoder.TryReadStreamedMips` 依赖这个索引的条目大小限制读取。`StarPakIndex.TryRead` 只检查整个文件范围，因此索引表本身的字节也可能被当成纹理内容读取。

最小夹具在修复前确认以下六类问题均返回成功：数据跨入索引、直接将索引当数据、超大条目、重复偏移、含负偏移的表、含零大小记录的表。重复偏移夹具把 4096 字节的条目静默替换为 1 字节。

修复后：

- 用 footer 和表长度计算数据区末尾，条目必须完整位于数据区。
- 用减法校验大小，避免 `offset + size` 溢出。
- 重复偏移及任何非法记录使整张索引失败，不能通过查询有效兄弟条目绕过。
- 失败索引不进入缓存；文件修复后，同一路径可以立即重新解析。
- 在创建字典前检查表字节数的整数转换，避免损坏 count 先触发大容量字典分配。
- 保留原有锁外 I/O、一次读取完整索引和缓存命中路径。

本轮没有添加未经格式证据支持的对齐或最小偏移限制，也没有改变有效的裸范围读取接口。
