## 2026-10-25 后续实现与证据

- 三个零售 DXBC 像素程序确认 Lyr 公式为 `saturate((ramp + 1) * vertexAlpha + ramp * (mask - 1))`；弹痕墙板 ramp 实际为 10。独立的第二层槽位现在保留颜色、Gloss、Specular 和 Normal；五组 GPU 输入通过，Traffic 墙板保留局部弹痕，原先满墙黑孔消失。
- 普通程序、Lyr 与水均确认 BC5 坡度解码为 `xy * 2.867661 - 1.439453`、Z=1。普通表面和贴花接入此解码及带符号 UV 切线基；非 RPak 法线仍按自身格式解码。
- 22 个私有 shader 的材质标量/向量来源已审计并纠正，材质 cubemap 使用实际立方体输入。全部正式编译通过，新进程 Schema 检查通过，framebuffer/depth 等真实渲染属性仍保留。
- 原始 RDEF 保留 unused 字段；此前将其中的 `c_perfSpecColor=0.03` 当成有效颜色，额外压低反射。现按 D3D_SVF_USED 判断是否采用，未用字段回到语义中性值。
- 水面保留两张扰动图与原版 UV 采样顺序，去掉原生参数已有时额外叠加的猜测流速。零覆盖度控制场景与背景逐像素一致。
- Traffic 的岸边横纹确认来自背景副本重写：即使旧 shader 的覆盖度为 0，真实地图仍有横纹。现采用水体内部折射、岸边预乘透明合成，并正确读取 framebuffer 的视口比例；同机位真实地图的横纹消失。水仍偏平、缺少校准后的反射与深浅变化。
- 实验 BSP 光照 shader 显式传递 TEXCOORD1，继承 Lyr/法线/反射参数。SKY A 使用 `rgb * (alpha * 3.984375 + 0.015625)`，SKY B 使用 `rgb * 2.007874 - 1` 的方向项；用烘焙值替代间接漫反射而非重复加亮。四象限 UV GPU 测试通过；Traffic 两页真实数据载入且无 Error 日志。
- **实验光照继续默认关闭**。当前天空色仍沿用环境光近似换算；静态物件探针、RTL、HDR 曝光未校准。此时全局开启会让地形与道具使用不同的间接光，不能当作完整修复交付。

证据目录为本会话 `tf2-material-completion/`：`layer-render-check.json`、`descriptor-cache-check.json`、`shader-schema-check.json`、`traffic-water-authored.png`、`traffic-water-composite-fixed.png`、`water-edge-zero-coverage.png`、`water-edge-final-zero-coverage.png` 与 `traffic-baked-lightmap-test.png`。可重复 GPU 检查见 `Perf/MaterialVerification/`。

下一工作包：默认模式多地图回归和冷/暖缓存对照，随后校准物件 SH 探针与 HDR 天空色，再决定何时默认启用 BSP 光照。不会通过统一调亮、删除所有顶棚或增加全地图实时反射来掩盖剩余差异。

### 默认模式回归及缓存结果

Traffic、Angel City、Homestead 已分别进行实际运行和固定机位检查。Angel City 四方向天空保留，57 个水面分区与 1 个独立天空组件正常存在；Homestead 的岩石、植被、建筑材质完成四方向检查。仍有整体偏暗、探针/曝光与水面反射差异，不以“能加载”代替画面一致。

额外修复两项实际运行问题：

1. 错误模型资源返回 `IsError=true` 的独立包装，旧代码只比较 `Model.Error`，使重试缓存和完整模型回退失效。所有挂载模型消费者统一使用有效性检查；实际包装与重试缓存测试通过。
2. Homestead 的物件元数据含非有限 LightingOrigin 值，原缓存序列化失败，地图无法缓存。缓存现无损保留这些值；它们的原版字段意义仍须在探针工作包中核对。2883 个世界 mesh、1941057 个顶点及同数量索引、PVS、物件信息与源解析逐项一致。

同一开发验证 DLL（`D3062352...`）、相同设置、两个独立游戏进程的一次配对实测：

| 阶段 | 首次建立缓存 | 第二次读取缓存 |
| --- | ---: | ---: |
| Homestead BSP 读取/解析/缓存 | 2.89 s | 0.59 s |
| 世界材质阶段 | 22.93 s | 0.29 s |
| 道具加载阶段 | 60.13 s | 1.99 s |

第二次道具阶段：302 个模型、595 张纹理命中派生缓存；材质 156 次命中、1 次旧材质路径未命中；0 拒绝、0 写入失败。这些是阶段计时，不是所有机器的整段加载保证。冷导入仍会受包解压、GPU 创建和驱动首次编译影响，开发中更换 DLL 也会主动使缓存失效。

当前视角的一次 Angel City GPU 采样中，主要开销是 opaque forward（约 3.06 ms），透明约 0.53 ms，3D 天空主阶段约 0.17 ms；显存约 2457 MiB。该机位 GPU P50 约 5.79 ms，截图预热有高峰，不能与用户不同分辨率/机位的占用百分比直接比较。继续优化应围绕不透明材质采样、原始 LOD 与遮挡，不能再次通过短距离隐藏大模型和阴影制造跳变。希望降低持续占用时，可以按显示器目标帧率设限；本次未改用户的全局帧率和画质设置。

后续复杂工作的优先级为：正确的物件 SH/LightingOrigin 字段与 HDR 天空色 → 默认启用前的 BSP 光照跨地图校准 → 水深吸收、反射与特殊透明材质 → 剩余粒子/音频事件和高 mip 动态升级。默认稳定路径继续使用现有原生光照与静态环境探针。

最终交付切换为启用优化的 **Release** 挂载 DLL，SHA256 为 `B07C6C3E88EDDBB93984E7182D6791B09EF321CEC5261828ED13A72EE1CE79AD`；源构建产物与部署路径一致，运行时确认 JIT 优化启用。Release 的混合、零覆盖度和光照 UV GPU 检查通过；开发验证版的计时不作为 Release 的固定性能保证。

## 1. 10-24 诊断基线与范围

图中有三类独立问题：特殊材质没有按原意执行、通用材质转换丢失数据、原版的光照与后处理尚未完整接入。另查到一个共同的参数声明错误：水与旧双纹理材质把应由 `Material.Set` 写入的参数声明为了 `Attribute`，GPU 实际读取场景对象属性或默认值。不能用一组亮度参数同时修复这些问题。

| 现象 | 已确认的数据或代码原因 | 本次处理 | 完整还原难度 |
| --- | --- | --- | --- |
| 顶层大片纯黑 | 命中 `mp_lf_fakesky_02` 的顶棚平面；第二层天空立方体绑定到 `Texture2D`，且纹理启用开关读不到材质写入值 | 增加立方体材质路径并纠正材质参数声明，按视线方向投影，保留第一层扫描线 | 基础显示可小修；全息效果的第二套 Fresnel、滚动与原版投影需要继续比对 |
| 墙板密集黑斑 | `uberLyrVcolt...` 的损坏层与干净层被压成单层；`layerBlendTexture` 还被误认为可乘的细节颜色 | 将混合权重、细节法线、细节遮罩分开分类，不再作为颜色相乘；停止将 `c_layerBlendRamp` 当细节强度 | 黑斑并未因此全部修好，必须实现真正的第二层混合 |
| 水面接近黑色、像不透明色块 | 重复深绿色乘数；统一覆盖度下限；法线和 UV 参数被误声明为场景属性 | 中性颜色乘数、覆盖度分离、修正材质参数及 BC5 法线 Z 重建 | 深度吸收、完整反射及第二套 Distortion 仍需专门实现 |
| 整体偏暗、金属和墙面缺乏层次 | 默认不使用 BSP 烘焙光照；静态物件的原版光探针未可靠解码；通用表面使用顶点法线，Specular/Gloss 仅近似转为 Metalness/Roughness | 本次保持全局灯光、曝光和用户画质设置 | 需要分阶段校准材质、烘焙光照、环境反射和后处理 |

这是差异定位与一批有限修复，不代表画面已经达到原版一致。原图的武器、机位和曝光也不同，不能直接以两张图的像素亮度作为准确的光照误差。

## 2. 黑顶：实际是全息屏幕顶棚

### 证据

- 向上射线从 `(300,1800,240)` 命中 `mp_lf_fakesky_02`，高度约 `672`。
- 地图有 6 种 `models/mp_livefire/mp_lf_fakesky_*.mdl`，共 18 个高处实例。
- 顶棚基础材质为 `world/test/kodai_fake_screen_01_world`，另有 `models/kodai/kodai_fake_screen_alpha` 的叠加网格层。
- 原 VMT 关键参数：

  ```text
  UnlitTwoTexture
  $basetexture effects/dev_scanline_small_mip
  $texture2 skies/skycube
  $layercolor1 [0.3 0.6 1.0]
  $layercolor2 [2.2 2.2 2.2]
  $addlayers 1
  $boomtownScrolling 1
  ```

- `skycube` 实际是 `1024×1024×6 / DXT1`，六个面有正常云层和地形内容。
- 旧运行日志重复出现 `Bad texture dimension 4 ... wants 1`。直接覆盖顶棚场景对象为白色后，黑区变白，确认遮挡来自该模型。
- 关闭普通金属屋顶 aggregate 不影响黑顶；改变 3D 天空模型也不能穿透这个不透明屏幕。

### 小修复

`LegacyMaterial.cs` 根据第二层纹理的立方体维度和不透明模式选择新 shader。新 shader 用材质输入 `CreateInputTextureCube` / `CreateTextureCube` 绑定立方体，避免把只适用于场景渲染属性的声明当成材质纹理输入。

另外，旧 shader 的 `g_flVmtHasTexture1/2` 默认是 0，并带 `Attribute(...)` 声明。运行时 Shader Schema 明确返回 `SourceType=__Attribute__`；`Material.Set` 虽然能读回数据，绘制时却继续按场景属性读取默认值。直接给 `SceneObject.Attributes` 写开关可使黑顶开始输出，验证了此问题。本次把旧双纹理系列与水 shader 的这些标量、向量改为材质参数，保留 framebuffer copy 等真正的渲染属性。

保留顶棚几何、扫描线和网格叠加，不通过移除整片顶棚掩盖问题。没有全局重新打开额外的 2D 天空。

### 后续

原版 `$boomtownScrolling` 的投影、第二套 Fresnel 和层合成尚未精确复现。先在正视、斜视和边缘机位记录这三个量，再决定是否需要专门的全息屏幕材质。不能继续用整体提亮来替代它们。

## 3. 墙面：需要真正的双层表面

代表材质：`world/s2s/s2s_painted_metal_01_bullets_bm`。

| 原版槽位 | 资源/用途 | 旧导入行为 |
| --- | --- | --- |
| `albedoTexture`，t0 | 带密集弹痕的颜色层 | 被当作整片墙的唯一颜色 |
| `normalTexture` / `glossTexture` / `specTexture` | 第一层法线和反射参数 | 通用路径只近似使用 Gloss/Specular，忽略法线 |
| `layerBlendTexture`，t22 | 两个表面的混合权重，`...bulletholes_01_bm` | 被误当作 Detail RGB，直接乘颜色 |
| `albedo2Texture`，t23 | 干净的 `s2s_painted_metal_01_col` | 与第一层语义相同，被“只绑定第一个”规则丢弃 |
| t24–t26 | 第二层 Normal/Gloss/Specular | 同样丢弃 |

本次只纠正数据类型。直接选用干净的第二层能去掉弹痕，但会丢失地图作者放置的损坏与污渍，因此没有全局使用这种替换。

下一步应实现独立的 `Lyr` 材质路径：

1. 在描述中保留层索引，而不是仅有 `Albedo`、`Normal` 这种单一语义；缓存同样保存层索引。
2. 核对 `c_layerBlendRamp`、遮罩通道、顶点颜色/Alpha 的真实含义和混合方向。先用全 0、全 1、渐变三个诊断输入验证，不凭黑白外观猜权重。
3. 分别采样两层颜色、Gloss/Specular、法线，然后按原版权重混合。法线需先转换到共同坐标空间并归一化，不能把 RGB 当颜色线性混合后直接输出。
4. 覆盖 `Vcolt`、`Vcola` 与不同 UV 变体。当前世界顶点保留颜色，但普通表面 shader 并未完整消费所有原版层控制。
5. 只给需要混合的材质增加第二组采样，保持普通材质的纹理上传与绘制成本。

验收：Traffic 墙板不再满墙弹孔，局部损坏仍按原图存在；河床、锈蚀面板、湿混凝土不能因修墙而变成统一材质。

## 4. 水面：基础颜色修正之后仍缺什么

当前具体材质是 `world/water/waterfall_stream_red_01`，不应仅凭名字中的 waterfall 把水平水面当作普通瀑布。

实测参数包括：`VcolaTrans`、`Uv1at`、`Uv2at`，第一 UV 缩放 1.5、速度 `(-0.03,0.03)`，第二 UV 速度 `(0.025,0)`，两份 Distortion，法线纹理为 `ATI2N`。旧实现只绑定一个 Distortion，且叠加了按文件名猜测的流速。

本次修正：

- 水颜色默认乘数从 `(0.18,0.32,0.30)` 改为 `(1,1,1)`。源 Albedo 已含红褐色，再乘深绿会把线性颜色压得很低。
- 将水体覆盖度与水体内部不透明度分开。纹理 Alpha 为 0 时仍可保留水体，但作者标记的岸边顶点 Alpha 为 0 时应回到原背景。
- 将法线开关、UV 变换、流速、颜色等改成实际的材质参数，使 `Material.Set` 的源数据进入 shader。
- 仅对实际 `ATI2N` 法线启用双通道解码，从 XY 重建 Z，其他法线格式保持原路径。

后续水材质应独立完成：

1. **法线与运动**：本次已补 BC5/ATI2N 的 Z 重建；继续核对强度、第二套 UV、两份 Distortion，避免原版动画和猜测流速重复叠加。
2. **反射**：先接稳定的地图环境探针，再评估可选 SSR。水是介质表面，不能用近似金属度代替反射参数。SSR 只能补充屏幕上可见的内容，须保留探针回退。
3. **透射/深浅**：用场景深度与水面深度之差估计厚度，按厚度控制颜色吸收，浅水看见河床、深水逐渐着色。不能让统一的 0.84 下限决定所有水面。
4. **岸边与排序**：延续独立的 `Titanfall2WaterRenderer` 与 framebuffer copy；水面不得重新并入普通 aggregate。检查覆盖度为 0 时无背景着色、无折射拖拽前景物件。
5. **成本**：先不增加整图实时平面反射。SSR、反射分辨率和更新频率应分别做同机位 GPU 帧时间对照。

验收机位至少包括正视/掠射、浅滩/深水、静止/移动及低/高画质。反射从屏幕外消失时不能突然整块变黑。

本次最终水面截图仍能看到部分岸边黑线和过于均匀的红褐色，反射层次也不足。这些作为尚未解决的折射/边缘合成问题保留，不能把“颜色变亮、波纹开始执行”等同于完整还原。

## 5. 光照：可修改，但不是简单调亮

### 当前明确的缺口

- `Map.cs` 默认 `parseLightmaps=false`，静态物件也 `parseStaticPropLightProbes=false`。
- `Map.Environment.cs` 以 `light_environment` 生成方向光和环境填充；`TryParseSourceLightColor` 采用亮度换算与上限，不是原版 HDR/曝光管线。
- 实验 `titanfall2_world_lightmapped.shader` 和光照页读取已存在，但解码及原版组合尚未验证完整，不能直接全局开启作为“还原成功”。
- 物件预载写入白色 ProbeColor，因为原版 LIGHTPROBE_INDICES 并非已确认的一物件一索引表。错误使用它比缺少它更差。
- Traffic 已导入 4 个内嵌环境 cubemap。存在探针不等于每个 shader 都已正确绑定和使用它，也不等于已经恢复烘焙漫反射。
- 普通表面 shader 当前使用顶点法线，法线图未进入着色；Gloss→Roughness、Specular→Metalness 是近似。
- 普通 PBR、透明、贴花等系列还有相同形式的 `Attribute` 参数声明。它们需要逐系列核对：材质常量改为材质输入，真正的逐物件属性保留，原版环境立方体也须核对绑定。不能只批量删除所有 Attribute 而不回归各条绘制路径。
- 按用户之前的需求，挂载地形与物件的动态投影默认关闭，原生接触阴影仍保留。现在缺少的空间明暗层次，不能仅归因于这一个设置。

### 建议顺序

| 顺序 | 工作 | 原因 | 完成标准 |
