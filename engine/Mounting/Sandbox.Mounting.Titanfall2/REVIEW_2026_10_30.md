# Titanfall 2 挂载审阅、性能与碰撞报告

日期：2026-10-30。工作区原有大量未提交修复，本轮保留它们，在当前实现上继续验证和改进。下文只把实际重跑的结果列为本轮证据。

## 性能结论

Steam 原生 renderer、实际 `mp_angel_city`、同进程 PID 29488，按 A → B → A → B 重新实例化同一张图。A 为每 cell 一个批次，B 为 4×4 cell 一个批次；每个阶段分别测街道、庭院、草地，街道相机固定为 `(2101.92,-1914.86,180.0312)`，旋转 `(0,94.5,0)`，FOV 90。

使用 `-novsync`，VSync 仅通过启动参数关闭；视口为 1920×1080。四个阶段都保留 19,455 个静态 prop，保持相同纹理上限、显示距离、逐实例 LOD、光照与碰撞配置。相邻两个测量窗口间隔 2.5 秒；各阶段先等待加载结束和机位稳定。测试期间不同时构建或运行离线几何审计。

| 街道阶段 | 批次 | FPS 两个窗口 | CPU ms 两个窗口 | Render ms 两个窗口 | GPU ms 两个窗口 |
|---|---:|---|---|---|---|
| A1：1×1 | 5,559 | 51.6 / 53.2 | 19.37 / 18.79 | 17.92 / 17.60 | 7.96 / 7.97 |
| B1：4×4 | 2,717 | 62.1 / 63.6 | 16.11 / 15.73 | 14.97 / 14.59 | 8.06 / 7.99 |
| A2：1×1 | 5,559 | 51.3 / 52.5 | 19.49 / 19.06 | 18.29 / 17.86 | 8.17 / 8.16 |
| B2：4×4 | 2,717 | 58.1 / 61.5 | 17.21 / 16.27 | 15.99 / 15.00 | 8.08 / 8.05 |

均值：**52.15 → 61.33 FPS（+17.6%）**；CPU **19.18 → 16.33 ms（-14.8%）**；Render **17.92 → 15.14 ms（-15.5%）**。八个街道窗口 CapWait 全部为 0。批次数减少 51.1%，GPU 时间约 8 ms，收益来自 CPU 提交。

这是短窗口固定机位测试，不是全图最低帧率保证。B2 有波动，报告保留全部窗口。A1 三角形为 2,765,149，其余三阶段为 2,769,901；地图粒子启动/动画与较粗的保守批次边界会使统计略变，未通过隐藏实例取得收益。A2/B2 三角形数量相同。原生 DrawCalls 没有随自定义对象数等比例下降，不把它当作实例批次数。

庭院与草地也已测量。庭院部分窗口触及失焦 90 FPS 上限、部分转为 GPU 受限，不能用两者的 FPS 计算 CPU 优化收益。草地未受限窗口也有改善，详细数据保留在原始 JSON 中。

### 采用的实现

- 将 `SBOX_TITANFALL2_PROP_BATCH_CLUSTER_CELLS` 默认值设为 4；设为 1 可恢复旧粒度。该值仅在初始化新 streamer 时读取，运行中更改不会重建已有批次。
- LOD 和距离判断仍按实例进行，重排后的 source index 保持探针身份；批次的 PVS、原生 bounds 和阴影状态采用保守合并，可能额外提交边缘实例。
- 保留最多八张精确子集索引表，命中时复用 GPU buffer，避免同一 LOD/裁剪子集每次绘制重复同步上传。增加 `ReuseSubsetIndices`，可在同一进程恢复每 draw 上传，单独测量。identity 索引复用由原有 `ReuseIdentityIndices` 控制。
- 没有采用实验性的 shadow pass 跳过探针绑定；保留此前已验证的 DepthPrepass 快路径。

|---|---:|---:|---:|---:|
| 关 1 | 61.5 | 16.27 | 11.56 | 46,665 |
| 开 1 | 64.5 | 15.50 | 7.99 | 0 |
| 关 2 | 65.2 | 15.34 | 11.47 | 50,020 |
| 开 2 | 65.2 | 15.34 | 8.09 | 0 |

GPU 均值 **11.52 → 8.04 ms（-30.2%）**。CPU 受限时第二对 FPS 完全相同，不能把这项描述为稳定的 CPU 帧率提升。另一个草地同进程对照从约 127.7 → 155.1 FPS、GPU 7.83 → 6.24 ms，说明缓存也会在 GPU 成为瓶颈时转化为 FPS；该组上传计数没有跨帧采样，不采用其计数字段。最终街道计数已用真实跨帧窗口重新验证，开启窗口分别有 313,775 / 311,850 次索引复用。

## 已修复的碰撞问题

### 实例删位结果完全为零仍创建实体

原版 `engine.dll` 的静态 prop 初始化器在 `0x1801affc4..0x1801b0007` 执行：solid/零内容展开、window/grate 展开，最后 `contents & ~collisionFlagsRemove`。本机原版 SHA256 已重新核对为 `58EB1A1B44B30275BDD21368DE264D856BC310D37D93A0F76F111F0026913487`；反汇编证据保存在 `.tmp/tf2-collision-audit/contents-native/engine.asm`。

挂载原来只记录删位元数据，仍直接创建 `ModelCollider`。现在按原版完整 uint 规则计算有效 contents，并仅在已知实例身份、已知 MDL 元数据且结果**完全为零**时跳过物理体。该实例单独计数，不算“碰撞资源缺失”，常驻碰撞 ready 的完成条件也计入它。旧 v3–v5 或未知来源继续保留原行为。

**没有按玩家 mask 直接删除非零 contents 的 prop。** 子弹、泰坦、抓钩可能仍需命中它们。诊断输出新增有效 contents，可继续据此研究分类。

### 恢复依赖后 ready 延迟

原生回归重现：世界碰撞清空后重新赋回，或 prop streamer 再启用，ready 会继承上一次 0.25 秒扫描限流。现在依赖失效时撤销 ready 并重置重试资格，依赖恢复可立即检查；连续有效但物理体数不匹配时仍保留扫描限流。

### Tricoll 绕序核实与测试夹具

当前读取器已将原版 tricoll 的 clockwise 绕序转换为与挂载渲染和物理一致的方向。本轮没有为了让测试通过而反转生产实现。重跑真实天使城得到：772,899 个渲染三角形的 raw cross 与顶点法线相反，749 个同向；可匹配的非双面 tricoll 中 583,851 个与转换后的渲染绕序一致，299 个相反。

旧合成 fixture 自己使用了相反的源绕序。本轮修正其源数据，并额外断言背面不命中。原生测试覆盖两个独立凸 brush 保留通道、tricoll 单面、模型平移旋转后旧位置清空、新位置可查询。

## 原版与当前实现的差异

| 层 | 原版数据/行为 | 当前实现及限制 |
|---|---|---|
| 世界 CM | grid/geoset 引用 brush、tricoll、static prop，按 contents 参与不同查询 | 读取器保留 21 位索引、world/inline 归属；世界导入目前以 player-solid 子集构建空间分块三角网格 |
| 原始世界开关 | 原版直接使用 CM | `SBOX_TITANFALL2_ORIGINAL_WORLD_COLLISION=1` 选择 CM；默认仍为 filtered render-geometry fallback，不能把默认路径称为原版 CM 完全等价 |
| Inline model | 独立局部坐标碰撞，可随游戏实体移动 | 现有独立 brush 资源和原生变换回归通过；门、电梯、剧情逻辑仍需游戏侧实现 |
| Prop 形状 | 原版物理模型、solid 类型、MDL contents 与实例删位共同决定 | 优先 VPHY；缺失时仍可能使用 hitbox、render mesh 或 bounds fallback，这些是近似形状 |
| 查询分类 | 玩家、泰坦、子弹、抓钩等有各自 mask | 原始 contents 已保留并可诊断；尚未完整映射到 Source 2 的 collider/tag 和游戏查询 |
| 常驻/流式物理 | 原版查询静态数据 | pure-world 可要求常驻 prop；旧场景仍可能按相机锚点流式激活，不等于多玩家远端物理已全面验收 |

天使城原始 CM 中 11,725 个 solid prop 里有 4,658 个不属于当前 player-solid mask；战争游戏为 4,936 / 8,026。这说明“solid type 非零就让所有查询阻挡”不等价于原版，也说明不能把这些非玩家 prop 整体删掉。本轮只修复有效 contents 为零的确定情形。
