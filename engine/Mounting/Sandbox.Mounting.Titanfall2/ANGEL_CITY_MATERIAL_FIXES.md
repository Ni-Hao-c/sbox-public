# 天使城：草片、广告屏、地面覆盖层与水岸

日期：2026-10-26。依据：用户原版/挂载截图、安装包原始材质及像素程序、MCP 新进程 GPU 检查和天使城实际运行。

本轮修复了三个材质共因，并补上非贴花透明层的遮罩。阴影、原版色调和港口水体仍未达到原版效果，不能将下面的材质检查当成全图还原完成。

## 已修复的直接问题

### 水边草变成整张绿色卡片

`MaterialLoader.IsWaterMaterial` 原先用文件名是否包含 `water` 判断水体。`models/foliage/grassblades_water_02` 实际使用 `uberCavCutSamp22222_fix`，但被选成 `titanfall2_water.shader`，因而没有叶片裁剪。天使城的 `grassblades_water_01.mdl` 和 `grassblades_water_02.mdl` 分别有 7、97 个实例。

现在先尊重 Cutout、Additive、Decal、Unlit 和 Lyr 的材质语义，再匹配水体目录及已核对的水面命名族。原模型、纹理、密度与 LOD 保留。相同模型/机位的 LOD0、LOD2 检查均恢复叶片轮廓；其他七种草/蕨类模型也保存了两级 LOD 对照。

### 泥地出现深色多边形，过渡被截断

同一条宽泛规则还把 `world/mud/mud_relic_dark_01_water_mud_bm`、水洼混合地面、水车金属、热水器和部分 Backwater 模型当成水面。该泥地原本是 `uberLyrSamp222222222_wld`；误选水体不仅改变颜色和反射，还令 `UsesLayeredSurface` 关闭，第二层和混合遮罩都不再使用。

现在该泥地恢复普通双层表面。实际庭院机位 `3300,300,1000` 朝向 `3400,1000,160` 中，原先大片黑色覆盖多边形不再出现，泥、草、岩石的地表过渡重新可见。独立真实水面仍保留水体路径。

### 电子广告变成竖条

广告的 UV1 经常有极小或为零的纵向比例，用来让扫描发光层随时间变化。旧代码给普通表面所有贴图统一套 UV1，导致本来应使用 UV0 的海报内容也被压成一行。

另外，`emissiveTexture` 与 `emissiveMultiplyTexture` 被归为同一个槽位，后者没有绑定，其 UV 选择却可能覆盖前者。新增独立 `EmissiveMultiply` 语义、贴图、开关与 UV，按原版程序将扫描层乘到发光图上。普通、裁剪、透明和世界烘焙表面均消费相应输入，世界材质复制也保留新参数。

原版 `tiffany_coffee_01` 像素程序直接使用 UV0 采样 t0/t4/t15，变换 UV1 采样 t17，再将 t17 与 t4 相乘。UV 选择串中的 Emul 项紧接主 Emission，而非按 t15/t17 寄存器排序；已纠正这个例外。当前天使城固定机位可以读出 TIFFANY'S COFFEE 的二维文字。

未处理的普通 `Uvd` 变体保留原有扰动坐标路径；本轮没有把未核实的扰动方式统一替换成无扰动采样。广告的细节法线和全部特殊调制变体仍需继续核对。

### 岸边白浪露出三角形轮廓

`world/homestead/homestead_water_whtwsh_slow_01_btt` 是 `Lyrtrans + Opam + Trans` 覆盖层，不是应强制保留水体不透明度的主水面。原版像素程序用混合遮罩和顶点 Alpha 得到覆盖度：

```text
weight   = saturate((ramp + 1) * vertexAlpha + ramp * (mask - 1))
coverage = 1 - weight
opacity  = coverage * albedoAlpha * opacityMultiply * materialOpacity
```

现将 Lyrtrans 透明覆盖扩展到非贴花表面；普通 Alpha、预乘透明与加法路径均可消费相应覆盖度，普通材质的独立顶点 Alpha 行为保留。该白浪在运行场景中使用 `titanfall2_translucent.shader` 且 `g_flT2LayeredOpacity=1`。水岸完整外观仍未关闭验收：主水面仍偏暗，扰动、反射与泡沫层次还需按原版校准。

## 仍需完成的复杂问题

1. **阴影与整体光照。** 当前默认路径的 `MapShadows`、`PropShadows`、`BSP_LIGHTMAPS` 均关闭；所以截图缺少完整建筑/道具投影有配置与接入原因，不能靠改阴影贴图分辨率解决。已有实验烘焙太阳遮挡与模型 SH，需要继续接入原始局部灯，检查室内外及道具接地，再决定默认启用。目标仍是稳定明暗，不恢复随距离开关的跳变阴影。详见 `LIGHTING_DATA_AUDIT.md`。
2. **曝光、雾与颜色。** 实验 Hable 固定曝光是基线，不是零售色调曲线/LUT。以同位置的室外、阴影、室内三组参照，先校准线性光量与反射，再处理曝光和雾；不能只用全局提亮/加灰来匹配一张截图。默认根 ColorAdjustments 目前没有有效后处理体积，不能把配置值当成已生效。
3. **港口水面。** 区分主水面、泥地、岸边白浪后，仍需核对原版主水面的不透明/折射语义、深度吸收、粗糙度与环境反射。当前港口固定机位仍偏黑，尚未恢复原图浅蓝灰色、细碎反光与柔和岸线。不要以“覆盖度控制检查通过”宣称水体还原完成。
4. **显存与帧时间。** 用户截图明确报告显存预算超限，验证过程中多个大型实例同时运行也遇到显存/内存不足。后续需在单实例、固定分辨率/机位下测实际纹理、模型、反射和预通道开销，设计可回收的纹理驻留预算；保住远景轮廓。当前仍是纹理单张尺寸上限，不等于总显存预算管理，本轮不宣称 GPU 占用率已经下降。

建议顺序：局部灯与稳定阴影 → 同机位曝光/反射 → 港口水深与白浪 → 显存预算和帧时间 → 将成熟的新光照数据纳入持久地图缓存。前面的可见材质错误已有独立修复，不需要等整套光照完成才可使用。
