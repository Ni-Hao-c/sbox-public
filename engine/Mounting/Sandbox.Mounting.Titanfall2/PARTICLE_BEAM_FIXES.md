# Titanfall 2 光束与粒子修复记录

本轮补齐连续光束和速度拖尾的基本渲染路径，并修复地图特效队列、发射数量、材质照明和生命周期问题。验证以本机零售 PCF、真实 GPU 绘制及地图运行为依据。能够解析文件不等于完整还原原版特效。

## 主要修复

### 光束和绳带

此前 PCF 能识别 `render_rope`，工厂没有对应渲染器，单独的绳带系统会创建失败，复合系统中的光束部分则被省略。

新增 `Titanfall2ParticleRopeRenderer`，每个集合使用一个 `SceneLineObject`。按粒子的创建顺序连接节点，支持逐节点颜色、透明度、半径、贴图坐标、偏移和流速，以及受上限约束的 Catmull–Rom 细分。保留原贴图，横向边缘夹取、纵向滚动循环；绘制边界包含实际宽度。组件禁用时释放原生对象和缓冲，重新激活后重建。

`titanfall2_particle_rope.shader` 使用预乘透明混合，支持普通透明、加法及 SpriteCard 的 add-self 项，转发 `$overbrightfactor`，并处理软交界和场景雾。亮度、加法和 add-self 参数通过绘制对象的属性传递；实际 GPU 检查确认亮度变化会改变画面，而不是只改变 C# 字段。尚未完成所有 Source 特殊混合和色彩空间的逐像素校准。

### 端点与路径

新增控制点上下文：子系统继承父系统控制点，也可保留 PCF 中设定的局部控制点。支持顺序路径初始化、持续贴合路径、到控制点距离的半径/透明度映射，以及控制点到颜色的映射。

地图导入现在从 BSP、FX、脚本、出生点和环境分区中查询具名目标，把 `cpoint1`–`cpoint63` 引用的位置保存到粒子实体数据。数据格式升为版本 3，保留版本 2 的读取兼容性。`SetControlPoint` 可供挂载内部持续更新端点；当前具名地图目标保存的是导入时的位置，尚未自动绑定移动实体。

支持 `emit_instantaneously by distance`：按端点距离和原始 spacing 计算节点数量，并遵守该集合及挂载的粒子数量上限。路径开启 `use existing particle count` 时使用实际发射数量铺满全程，避免超过固定计数后绕回起点。零售 `P_beacon_beam_small` 的 500 单位检查生成 32 个节点，首末节点均准确落在端点，数量受原集合上限约束。

### 火花与拖尾

原来把“拖尾时间”和“渲染器世界空间长度上限”混用，容易产生过长拉丝。现在在模拟完成后，以 `速度 × 拖尾秒数` 计算长度，再应用独立的最小/最大长度、淡入时间和半径约束；朝向跟随速度，粒子位置作为头部，关闭重复的运动模糊拉伸。

核心 sprite compute shader 增加零投影速度检查，静止或直接朝向相机移动时保持既有旋转，避免对零向量归一化后产生无效顶点。

### 颜色和发射

- PCF 集合根节点的颜色、半径、透明度现在作为默认值读取，再由初始化器覆盖。
- `SpriteCard` 按原材质路径处理为不依赖场景照明的卡片，修复暗处火花接近全黑的情况。
- Sprite 的 `$color`、`$alpha` 和 `$overbrightfactor` 转发到粒子 tint，使用引擎既有 RGBE 路径保留 HDR 颜色；控制点颜色映射保留该材质乘数。
- 发射器组件启用时会先缓存默认 Burst=100。设置 PCF 参数后重新初始化其缓存，修复实际发射数量超过原定义的问题。
- 瞬时发射只触发一次；连续发射按原发射时间运行，零时长连续发射持续到被停用，不再按粒子寿命反复重启。
- 仅有 end-cap 衰减的光束保留粒子，避免寿命到期后周期性断开；同时含正常衰减的集合仍保留正常寿命。
- end-cap 专用初始化、运动和淡出操作不会在普通运行期间提前执行。`glow_imc_light03_wide` 的结束阶段淡出曾让常亮卡片在一秒后消失；现在持续显示到特效停止。
- Sprite 读取原始可见性输入，支持距离淡出、朝向点积映射和背向剔除。常亮卡片不会因为恢复生命周期而在背面和过远位置始终显眼。完整的可见性探针遮挡半径与非零控制点方向仍有还原空间。
- 不再把所有子系统都失败的父系统算作成功；无法渲染的空分支会被清理。

### 地图队列

实际地图验收暴露了此前的队列错误：目录扫描完成后，剩余队列直接被归类为“定义不存在”。但分帧创建有时间和数量预算，队列中大多数仍是有效特效。虎大第一次验收因此仅保留 282 组中的 1 组。

现在目录完成时只删除确实查不到定义的名称，保留有效队列继续分帧创建。初始化也会等待实体数据就绪，避免组件先启用、后赋值时永久跳过初始化。

## 可重复检查

脚本位于 `Perf/ParticleVerification/`，通过 sbox-cli 的 MCP `run_csharp` 在隔离临时场景运行，输出截图和 JSON 到该次连接的 `exchangeDirectory`。

| 检查 | 范围 |
| --- | --- |
| `VerifyParticleGeometry.csx` | 23 项：真实光束、火花、蒸汽、复合采集器和地图信标的 GPU 可见性，12 节点数量、端点跟随、按距离生成节点、HDR 参数、持续寿命、常亮卡片及方向/距离控制、禁用释放和重启、拖尾长度、单次/连续发射、零/平行速度、原材质 6 倍增亮 |
| `VerifyParticleMapData.csx` | 3 项：控制点保存后读取一致、旧版本地图兼容、无效控制点数量拒绝 |
| `VerifyParticleQueue.csx` | 2 项：目录完整时有效对象继续排队，随后全部生成，只有刻意缺失的名称失败 |

队列检查会记录一条预期的缺失定义警告 `__codex_missing_particle_definition__`。该警告属于测试输入。脚本读取和模拟真实原始资源，但不代表所有 PCF 操作器都已实现。

最终部署版本的 28 项检查全部通过：23 项几何与 GPU 检查、3 项实体数据检查、2 项队列检查。

零售库审计为 396 个 PCF、10437 个定义条目、10435 个去重名称，未发生 PCF 解析失败。其中 462 个定义带 Rope、2126 个定义带 Sprite Trail；这些数字描述文件覆盖范围，不作为全部效果正确的证明。

## 实景验收

殖民地已正常运行并保存固定视角截图。其 66 组常驻 FX 全部属于暂时屏蔽的烟雾/地雾，当前默认配置下不生成粒子，所以这张图用于地图与既有材质兼容性检查。

虎大 `mp_forwardbase_kodai` 用于检查正常地图加载、控制点传递、常驻光束和火花，以及分帧队列完成情况。最终运行数据和截图记录在本次会话的 `tf2-particle-improvements` 证据目录。

- 最终实景：282 组地图 FX 保留，0 待创建、0 失败；修复前同一地图仅保留 1 组、误跳过 281 组。
- `P_beacon_beam_small` 主光束：实际端点距离 119.95249，11 个节点，首末节点与地图具名目标一致，原生对象有效且正在提交。
- 常亮卡片在运行超过 241 秒后仍各保留一个粒子。方向和远距离隐藏另有受控 GPU 检查。
- 主光束已恢复；快照时 `bb_sml_CH_core1`、`bb_sml_CH_core2` 两个附属绳带分支不在提交状态，原版子系统重启及事件语义仍未完全恢复。这一项保留为后续工作，不把主集合正确当成整个复合特效完全一致。
- 最终地图运行控制台未记录 Error 级别输出。部分原有模型缺少碰撞体的警告仍是独立问题。

Release 构建 0 警告、0 错误，针对本轮 C# 文件的空白格式检查通过。部署文件 `game/mount/titanfall2/titanfall2.dll` 的 SHA256 为 `DAE170AB214DCDF47459ABD538234F0405AD8284974CA03D3F73C769BB53A38D`，与本轮构建输出一致。

## 当前边界与下一步

1. **天空世界粒子仍未接入。** 当前 3D 天空使用独立 SceneWorld，原 skybox 坐标不能直接放进主世界。下一步应在相同世界中建立模拟和 sprite/ribbon 提交，跟随 sky camera 处理尺度。
2. **大范围烟雾、蒸汽和地雾仍保留原有默认屏蔽。** 小范围 `impact_steam` 已通过渲染检查，不足以证明覆盖整张地图的 fog/smoke 卡片正确。应先分别验证尺寸、贴图序列、柔和交界、混合方式和 GPU 开销，再分组启用；不能直接解除全部屏蔽。
3. **移动控制点尚未自动绑定。** 当前地图引用是静态位置快照；应把具名动态实体或骨骼的位置按帧传入上下文，并测试销毁、重新生成及换图。
4. **贴图序列不完整。** 现有 VTF sheet 路径使用序列 0 的裁剪帧，动画按渲染器推进。逐粒子出生相位、随机序列、双序列、green/alpha 通道提取和颜色 ramp 需要后续支持。
5. **操作器仍为子集。** 更复杂的随机路径形状、径向速度、噪声、旋转、碰撞、end-cap 收束、事件和按粒子创建子系统未完全对应原版。出现具体差异时应回到对应 PCF/VMT，避免用统一名称规则掩盖差异。
6. **性能需按实际机位衡量。** 一条绳带一次提交，保留现有粒子数量、灯光数量和活动半径预算，不给粒子开启阴影。恢复原来缺失的特效会增加渲染工作，不能仅凭这一实现宣称 GPU 占用下降。后续优先按屏幕覆盖率和可见性调整预算，测试多组透明卡片叠加时的填充开销。

SpriteCard 参数和混合语义参考 Valve 官方 Source SDK 的 [spritecard.cpp](https://github.com/ValveSoftware/source-sdk-2013/blob/master/src/materialsystem/stdshaders/spritecard.cpp) 和 [spritecard_ps2x.fxc](https://github.com/ValveSoftware/source-sdk-2013/blob/master/src/materialsystem/stdshaders/spritecard_ps2x.fxc)，具体取值来自本机 Titanfall 2 的 VMT/PCF。
