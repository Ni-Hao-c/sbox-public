日期：2026-11-08。接续 Apex 转换项目兼容性审查。

## 探针叶节点：零售与转换器一致，原挂载代码错误

读取用户已安装 TF2 的零售 VPK，解压实际 BSP 的 LIGHTPROBE_TREE / LIGHTPROBE_REFERENCES / LIGHTPROBES。没有使用第三方项目的注释或测试结果作为零售格式的证明。

确认叶节点为：

```text

firstReference = tag >> 2
referenceCount = value
```

全部叶节点范围有效，每叶 1–4 条引用，全部引用各归属于一个叶节点，不重叠也不遗漏。该完整覆盖检查针对整个节点数组，而不只遍历 root 0；Beacon 的节点数组含 root 0 不可达的额外树数据。

此前代码注释采用“引用原点下降后仍在叶范围内”作为验证条件，这不足以排除字段颠倒：错误产生的大范围互相重叠，仍可能包含采样点。

修复 `Titanfall2LightProbeLookup.Find` 的 first/count 参数顺序，并修正原先也采用颠倒布局的合成测试。增加起始索引与数量不相等、空叶不能扫描邻接引用的回归。

另生成 3,010 个查询位置，用独立读取代码产生叶内最近引用的预期结果，然后调用修复后的生产 C# 查询，比较 RGB 系数、天空/日照系数、光源权重和四个光源索引。全部通过。旧字段布局在其中 1,345 个位置返回不同编号；这不是游戏画面错误率。

本次保留原来的“选定叶内查询”语义，没有把转换项目的全局 KD 最近点回溯直接用于零售地图。额外树的环境选择与原引擎跨叶查询行为仍需独立验证。

## 粒子通用修复

### 实体来源

现在合并 `_fx.ent`、BSP 主实体及 script/spawn/environment/sound 分区，既发现主实体里的发射器，也能跨分区解析命名控制点。跨分区的完全相同实体只导入一次，同一分区中作者明确放置的重复实体保留。

保留 `start_active=0/false` 的未启动状态；未接脚本启动事件之前，不把这些效果强制变成常开。`in_skybox` 的布尔值统一解析，天空粒子继续明确记录为 deferred。

### 父物体初始坐标

Beacon 的 14 个粒子实体带 `parentBrushModel=*3`，对应 script 分区里的 `func_brush`，父原点为 `(3651, -1989.52, 4322)`。旧代码把子实体局部坐标直接作为世界坐标。

例如一个 `warning_light_red` 的局部位置为 `(-510.09, -13.09, 207.39)`，正确初始世界位置为 `(3140.91, -2002.61, 4529.39)`。新的解析路径组合父平移与旋转，并同样转换命名控制点。真实 Beacon 数据回归已通过。

父引用无法解析或形成循环时，不在错误的世界位置生成效果，并计入日志。这里只恢复初始变换；父物体后续移动与玩法驱动的持续绑定仍未实现。

### 控制点覆盖

地图实体或运行时写入的世界控制点，现在可以覆盖子 PCF 集合中同编号的默认局部控制点；没有外部覆盖的控制点仍使用本地默认值。已用运行中的独立测试场景验证初始覆盖与后续更新。

### 子系统索引顺序

等待 PCF 目录索引完成，再创建系统树。原流程可能在父定义刚被发现时创建效果，而子定义还在后续 PCF 内，从而永久漏掉子效果。

目录索引仍按每帧文件数与时间预算推进。这个选择会在创建前完成全部目录索引，可能增加加载准备时间；避免了用不完整目录发布系统树。

### 实体预热与暂停

支持实体级 `warmup_time` / `warmup_and_pause`，并写入粒子实体序列化 v4。读取仍兼容旧 v2/v3，缺少的新字段使用零预热/不暂停默认值。

Beacon 实际存在 `env_smoke_plume_XLG_dark` 的 `warmup_time=40`，此前被忽略。现在按实体目标预热时间补足 PCF 已预热的部分，在加载阶段以小步分批推进；待处理效果保持暂停，避免加载帧重复推进。预热完成后恢复运行或保留暂停，直到全部预热完成才发布资源准备状态。实体输入限制为 0–60 秒。

独立原生场景测试验证：单步预算不会一次做完整预热；加载期间的额外 Step 不增加粒子年龄；完成后总年龄正确；暂停和继续运行两条分支均正确。

### 输入与诊断

过滤非有限 origin/angles，序列化解码也检查变换、预热及控制点。未解析控制点与父引用分别统计。继续忽略粒子实体的编辑器图标 scale，避免重复放大 PCF 已定义的世界尺寸。
