# TF2 环境与后处理调试记录（2026-11-09）

## 范围与状态

水和粒子保持当前方案。这份记录描述环境实体漏读、既有效果状态恢复与资源销毁的 debug 阶段；随后已随[局部调色与 Bloom 版本](TF2_COLOR_BLOOM_DEPLOYMENT_2026-11-09.zh-CN.md)完成构建、针对性检查和部署。本记录列出的全部场景并未逐项实图验收。

## 确认的代码路径问题

| 问题 | 原行为 | 源码修正 |
| --- | --- | --- |
| 环境定义漏读 | `_env.ent` 非空时，大多忽略 BSP 主实体中的环境定义 | 合并两处来源，天空、光照和后处理共用同一读取结果；消除跨来源副本，保留任一来源内实际作者数量；地图缓存丢弃时清理合并结果 |
| 重复环境索引覆盖 | 合并后的相同光照索引可能被后写的来源覆盖 | 第一个有效编译状态优先，保持外部分区优先顺序 |
| 退出局部环境不恢复 | 默认环境没有有效索引或完整编译状态时，Apply 找不到默认状态，保留局部的太阳和天空颜色 | 序列化 -1 默认光照快照作为回退；负索引不作为空间区域；停用时恢复默认光照 |
| 重新配置仍用旧环境 | Restore 看到旧 states 非空便提前返回 | 重新配置前清除旧状态、区域、灯光引用和当前索引 |
| 自动曝光重复启停失败 | 首次关闭后清掉控制权标记，再次 Render 时却不重新记录，第二次关闭无法恢复 | 每次重新取得控制权时记录相机当时的自动曝光设置，保留已有曝光历史纹理 |
| 调色表无法恢复 | 路径变更后仍持有旧表；一次加载失败后缺少启用时重试入口 | 记录已加载路径，路径变化后重置引用；重新启用时重试失败路径，同一次启用中不逐帧重复失败 |
| 全局调色分类过窄 | 要求两个 falloff 都为负，漏掉单端点为 -1 或两端相等的定义 | 按 Source 径向实体的衰减旁路条件分类；空 filename 不再遮住后续有效全局定义 |
| 非有限数值进入渲染 | float.TryParse 接受 NaN/Infinity，继续传到位置、旋转参数和调色权重 | 实体标量/向量及后处理最终权重均检查有限值 |
| Dispose 异常打断释放 | 单项资源抛异常后，剩余资源及 mount lease 都没有释放 | 单项释放分别捕获、记录异常，继续剩余资源与既有 lease 归还逻辑 |

全局调色判断参照 [Valve Source SDK 的 c_colorcorrection.cpp](https://github.com/ValveSoftware/source-sdk-2013/blob/master/src/game/client/c_colorcorrection.cpp)。这是共享 Source 实体语义的参考，不能作为 TF2 客户端扩展行为已经验证的证据。

## 数据与接口核对

- 本地已提取的 sp_boomtown_start、mp_angel_city、mp_wargames、sp_beacon、sp_tday 五份环境实体快照都使用全局 color_correction，falloff 两端为 -1；它们不能作为局部调色样本。
- 引擎 BasePostProcess 的同类效果由首个实例执行 Render；GetWeighted 插值数值，现有 TF2 Render 仍绑定一张 LUT。仅添加更多原生 volume 不会自动实现多表混合。
- 环境默认光照快照属于新导入的场景数据，旧的缓存场景需要重新导入才能取得这份快照。
- 本轮不销毁共享材质，不改活跃地图的资源所有权，也不扩展水和粒子实现。
