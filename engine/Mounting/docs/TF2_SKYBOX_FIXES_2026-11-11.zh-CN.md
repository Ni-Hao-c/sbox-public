# TF2 天空盒选择、动作晃动与高处接缝修复

日期：2026-11-11。生产修改仅在挂载项目的 `Resource/Map.Spawns.cs` 和 `Resource/Skybox3D.cs`；保留当前工作区的官方引擎适配改动，未改动引擎源码或 shader。本次修正已构建和验证，随后按用户授权部署到仓库运行目录和正式 Steam 安装；两个目标分别匹配其引擎程序集，见[部署记录](TF2_SKYBOX_DEPLOYMENT_2026-11-11.zh-CN.md)。

## 1. mp_eden 误选入场天空

直接读取零售 `englishclient_mp_eden.bsp.pak000_dir.vpk`，得到：

| 内容 | 位置 |
| --- | --- |
| `skybox_cam_level` | `-5688 7112 -4544` |
| 白天 vista：`models/vistas/eden_se.mdl` | `-5688 7112 -4696` |
| `skybox_cam_intro` 与 `planet_blue_sun.mdl` | `11680 -8896 -5120` |

地图 vista 的枢轴比 level 相机低 152 单位。原来的 16 单位匹配半径排除了白天模型，只剩与 intro 相机同位置的星球模型。

现在先将每个 vista 分配给最近的有效 authored sky_camera，再选择 level 组。保留模型原有位置和旋转，不将模型吸附到相机。缺少环境实体时仍使用原有非星球模型组回退规则。零售数据检查及官方引擎渲染均确认 Eden 选中 `eden_se.mdl`，没有混入 `planet_blue_sun.mdl`。

## 2. 天使城动作时晃动

原实现每帧设置桥接原点为 `CameraOrigin - Camera.View.Position / drawScale`，试图抵消原生天空盒的相机平移。

当前引擎的 `Camera.View` 是瞬时相机效果之前的视图。原生渲染相机还会加上武器 punch、shake 等效果，因而抵消所用的位置与最终绘制位置不一致。隔离测试中，基础视图为 `1200,-500,200`，施加相机 punch 后最终渲染位置为 `1200,-500.4696,205.3681`。

修正后桥接原点固定为地图 sky_camera 原点，由原生天空盒为每个最终渲染视图计算平移。移除了逐帧反射更新及相机位置缓存。普通视角、瞬时相机冲击和升高视角均保持 authored origin，避免基础相机与最终相机之间的抵消误差。

## 3. 高处外景与地面脱离

地图写入 `skyscale=1000`，原实现却按模型包围盒计算 `25000 / extent`；天使城得到约 `3.9134114`。再抵消玩家位置后，外景失去了应有的高度视差。

现在使用地图选择结果中的比例 1000，保留固定原点。已有仅用于 vista 的微小近裁剪投影保持不变；不调整玩家近裁剪面，也不放大或移动主地图。

在同一官方引擎进程中，以天使城相机 `2284,-1766,3000`、角度 `35,76,0` 检查地图边缘：先渲染新变换，再在同一组件上恢复旧比例及旧抵消公式作为对照。旧变换在地图边缘外留下大片黑色区域；新变换使外侧城市地形重新覆盖该区域。

这里的旧图是同进程重建旧变换的对照，不是重新运行旧 DLL；它隔离了天空盒变换这一项。尚未进行零售 Titanfall 2 客户端的同机位逐像素对照，也未验证任意高度、所有方位或实际手持撬棍动画。
